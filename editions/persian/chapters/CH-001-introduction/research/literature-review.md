# Literature Review

## Purpose

This document collects research foundations supporting Chapter 1.

The goal is not to summarize all existing knowledge, but to identify concepts that support the chapter narrative.

---

# 1. Software Engineering as a Discipline

## Key Idea

Software development evolved from individual programming activity into an engineering discipline because software systems became larger, more complex, and more critical.

## Supporting Sources

### Brooks, Frederick P. (1987)

"No Silver Bullet — Essence and Accidents of Software Engineering"

Main contribution:

Brooks distinguishes between:

- Essential complexity
- Accidental complexity

The paper argues that software complexity has fundamental limits that cannot simply be removed through better tools.

Relevance:

Supports the argument that AI-generated code alone does not solve software engineering challenges.

---

### Sommerville — Software Engineering

Main contribution:

Software engineering is defined as a systematic approach to the specification, development, operation, and maintenance of software systems.

Relevance:

Supports the transition from coding to engineering processes.

---

# 2. Agile and DevOps Transformation

## Key Idea

Software engineering evolved from sequential processes toward iterative development and continuous delivery.

Relevant concepts:

- Agile Manifesto
- Continuous Integration
- Continuous Delivery
- Infrastructure as Code

Relevance:

Provides historical context for another transformation caused by AI agents.

---

# 3. AI-assisted Software Development

## Key Idea

Large Language Models introduced a new category of software development tools capable of generating and transforming code.

Examples:

- Code completion
- Code explanation
- Refactoring assistance

Limitation:

These systems typically depend on human direction and review.

---

# 4. AI Agents

## Key Idea

AI Agents extend beyond generation by introducing:

- Goal orientation
- Planning
- Tool usage
- Iterative execution

Research Area:

Emerging field.

Requires careful distinction between current capabilities and future expectations.

---

# 5. Research Gap

Existing research explores:

- LLM capabilities
- Code generation
- Autonomous agents

However, software engineering requires additional concerns:

- Governance
- Traceability
- Architectural consistency
- Human-agent collaboration models

This gap motivates the concepts introduced in this book.
